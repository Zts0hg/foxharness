### P-2026-0808-17255q-1: Cancelling a shell context does not guarantee descendant termination
- claim: External commands that can spawn descendants require bounded output, process-tree supervision, TERM-to-KILL escalation, reaping, and cleanup evidence owned by the enclosing run.
- type: pitfall
- scope/when: executing shell, validator, Git, GitHub, benchmark, Autodev, or child-agent commands
- root-cause: cancelling or killing only the immediate shell leaves descendant processes alive; the parent may also exit before its group, permitting delayed side effects after the logical run has terminated.
- workaround: create a platform process-tree boundary before start, register it with the run owner, cap stdout and stderr independently, terminate the whole tree on cancellation or overflow, wait a bounded grace period, escalate to KILL, reap under a fresh bounded cleanup context, and include cleanup failure in the terminal outcome.
- lesson: process lifetime is part of run correctness, not an implementation detail of `exec.Cmd`; terminal success or failure is premature until owned descendants are accounted for.
