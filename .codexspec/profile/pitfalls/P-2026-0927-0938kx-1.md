### P-2026-0927-0938kx-1: A last-call test double loses request identity in asynchronous workflows
- claim: Test doubles shared by foreground and background model calls must retain correlated observations instead of exposing only the last call.
- type: pitfall
- scope/when: testing runtimes that reuse one provider for foreground runs and asynchronous memory extraction, compaction, or other background work
- root-cause: a concurrency-safe single-value recorder preserves memory safety but not request identity; whichever asynchronous call finishes last overwrites the foreground observation, so scheduler timing changes what the assertion inspects.
- workaround: record immutable observations keyed by a stable discriminator such as run ID or direct user input, then assert against the intended foreground call; explicitly wait for background completion only when that completion is itself under test.
- lesson: locking prevents data races, but deterministic asynchronous tests also require semantic correlation between each observation and the work that produced it.
