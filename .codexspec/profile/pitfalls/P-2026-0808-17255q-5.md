### P-2026-0808-17255q-5: `git add -A` sweeps build binaries produced at the repository root into commits
- claim: Stage commits with explicit paths (or ensure every build artifact is gitignored) — bulk staging collects compiled binaries alongside source changes.
- type: pitfall
- scope/when: any repository whose root `package main` (or build scripts) drop binaries at the tree root, when staging with `git add -A` / `git add .`
- root-cause: `go build ./...` writes the root main package's binary next to go.mod (here `./fox`); the file is untracked, so `git add -A` treats it as new content and commits a 34 MB Mach-O that nothing references.
- workaround: add `/fox` (and equivalent artifact names) to `.gitignore`; prefer `git add <paths>` or `git add -u` for source-only staging; audit `git show --stat HEAD` before pushing — a size outlier is the tell.
- lesson: every new build output name needs an ignore entry before any bulk staging command; review the stat line, not just the exit code.
- evidence.facts: the review round reported "A 34MB compiled arm64 Mach-O binary was committed at the repository root by the HEAD commit; it is not gitignored and nothing references it"; `git show --stat HEAD` confirmed the binary rode in with an unrelated fix commit.
- evidence.state: confirmed at feature 2026-0808-17255q; commit 556d1f9 (removed again by 5d5caea). Still valid — `/fox` is now ignored.
