# HTML 设计稿的 Go TUI 可实现范围

## 目的

本文用于约束 FoxHarness 的 HTML 设计稿，使设计效果能够使用项目当前的
Bubble Tea 和 Lip Gloss 实现。

起步阶段只遵守一条原则：

> 把 HTML 当作终端字符界面的预览工具，不把它当作浏览器网页。

设计交付只需要一个 HTML 文件。文件中展示目标界面，并通过注释说明终端尺寸、
交互状态和必要的降级行为。不要求额外编写 manifest 或 fixture。

## 当前技术边界

项目当前使用：

- Bubble Tea `v1.3.10`：状态更新、键盘输入、鼠标事件、窗口尺寸变化和定时消息。
- Lip Gloss `v1.1.1`：文本样式、颜色、字符边框、间距、宽高、对齐及横向和纵向布局。
- Termenv `v0.16.0`：终端颜色能力和终端背景适配。

终端界面由字符组成。一个中文字符通常占两列，一个英文字符通常占一列；组件的
位置、宽度、高度、边框和间距最终都必须换算为整数个字符单元。

## HTML 与 Go TUI 的等价能力

以下效果可以在 HTML 设计稿中使用。

| HTML/CSS/JS 效果 | Go TUI 等价实现 | 设计限制 |
| --- | --- | --- |
| 文本和多行文本 | 普通字符串和换行符 | 使用等宽字体 |
| `color` | Lip Gloss `Foreground` | 使用项目主题颜色 |
| `background-color` | Lip Gloss `Background` | 只使用纯色 |
| `font-weight: bold` | Lip Gloss `Bold` | 不设计多级字重 |
| `font-style: italic` | Lip Gloss `Italic` | 不作为关键信息的唯一提示 |
| `text-decoration: underline` | Lip Gloss `Underline` | 可以使用 |
| `text-decoration: line-through` | Lip Gloss `Strikethrough` | 不作为关键信息的唯一提示 |
| 弱化文本 | Lip Gloss `Faint` 或弱化颜色 | 优先使用弱化颜色 |
| 前景色和背景色互换 | Lip Gloss `Reverse` | 适合焦点和选中状态 |
| 单色边框 | Lip Gloss `Border` | 边框必须由字符组成并占用空间 |
| `padding` | Lip Gloss `Padding` | 只能使用整数列和整数行 |
| `margin` | Lip Gloss `Margin` 或空格、空行 | 只能使用整数列和整数行 |
| 固定宽高 | Lip Gloss `Width`、`Height` | 单位是列和行，不是像素 |
| 最大宽高 | Lip Gloss `MaxWidth`、`MaxHeight` | 必须说明超出后的处理方式 |
| 水平排列 | `JoinHorizontal` | 类似简单的单行 Flexbox |
| 垂直排列 | `JoinVertical` | 类似普通块级文档流 |
| 左、中、右对齐 | Lip Gloss `Align`、`Place` | 只能对齐到字符单元 |
| 文本换行 | Go 字符宽度计算后换行 | 不能依赖浏览器自动换行 |
| 文本截断和省略号 | Go 截断函数 | 必须在设计中展示截断结果 |
| 固定区域滚动 | Model 保存滚动位置并截取行 | 不存在浏览器原生滚动容器 |
| 输入框 | Model 保存输入内容和光标位置 | 光标占一个字符单元 |
| 按钮 | 文本标签加焦点或选中样式 | 没有浏览器原生按钮外观 |
| 单选、多选和列表菜单 | 字符标记加 Model 状态 | 必须展示当前焦点和选中项 |
| 卡片或对话框 | 字符边框包围的文本区域 | 不使用阴影和半透明遮罩 |
| 键盘交互 | Bubble Tea `KeyMsg` | 必须明确按键和结果状态 |
| 鼠标点击、拖选和滚轮 | Bubble Tea `MouseMsg` | 目标区域按字符坐标计算 |
| 窗口响应式布局 | Bubble Tea `WindowSizeMsg` | 使用明确的列数临界点 |
| 加载动画和进度条 | 定时消息切换字符帧 | 只设计离散帧，不设计平滑动画 |
| 焦点和失焦 | Bubble Tea `FocusMsg`、`BlurMsg` | 不依赖浏览器 `:hover` |

### 可直接设计的组件

基于这些能力，HTML 设计稿可以包含：

- 标题栏和状态栏
- 对话记录和 Markdown 内容
- 输入区和光标
- 命令建议列表
- 单选、多选和确认表单
- 侧栏和多栏布局
- 带字符边框的卡片
- 菜单、选择器和文本标签页
- 可滚动文本区域
- 进度条、加载符号和状态提示
- 键盘焦点、鼠标选择及滚轮状态
- 根据终端宽度显示或隐藏区域的响应式布局

“模态框”可以设计成一个优先显示的字符卡片，也可以临时替换主内容，但不能依赖
网页式半透明遮罩、阴影或真正的图层覆盖。

## HTML 设计稿禁止使用的效果

以下效果没有可靠的终端等价实现，不应出现在要求复现的设计区域中：

| 禁止效果 | 原因 |
| --- | --- |
| 像素定位和像素尺寸 | 终端只知道字符行和列 |
| 不同字号 | 字号由终端统一控制 |
| 自定义字体和多种字体 | 字体由用户终端控制 |
| 字距和自定义行高 | 由终端控制，应用不能精确设置 |
| 圆角半径 | 只能用 Unicode 字符模拟边框 |
| 阴影 | 没有可靠的终端等价效果 |
| 渐变 | 终端布局不适合逐像素渐变 |
| 半透明和毛玻璃 | 终端颜色没有网页式透明合成 |
| 图片、SVG、Canvas 和视频 | 当前 TUI 以字符和 ANSI 样式渲染 |
| `position: absolute` 精确叠层 | TUI 主要通过字符串组合形成布局 |
| `z-index` | 没有浏览器图层系统 |
| `transform` | 不能对子元素做像素旋转、缩放或位移 |
| CSS Transition | 只能通过重新渲染离散帧模拟 |
| 平滑滚动 | 滚动以整行或整列发生 |
| 仅在 `:hover` 时出现的信息 | 终端用户可能只使用键盘 |
| 依赖浏览器自动换行 | 浏览器和终端的字符宽度算法不同 |
| 未验证的 Emoji 或图标字体 | 不同终端中的字形和宽度可能不同 |

设计稿可以在终端画布之外使用普通网页样式制作切换场景的控制面板，但这些控制面板
不属于 TUI 设计，不应要求在 Go 中实现。

## 项目现有布局规则

设计默认沿用当前 TUI 的以下规则：

| 项目 | 当前值 |
| --- | --- |
| 最小终端宽度 | 60 列 |
| 外层上边距 | 1 行 |
| 外层右边距 | 2 列 |
| 外层下边距 | 0 行 |
| 外层左边距 | 2 列 |
| 最右安全空间 | 1 列 |
| 侧栏显示临界点 | 110 列 |
| 侧栏宽度 | 内部宽度的 26% |
| 侧栏最小和最大宽度 | 36 至 58 列 |
| 主内容与侧栏间距 | 3 列 |

如果一个新设计需要修改这些规则，应直接在 HTML 注释中说明。没有说明时，实现按照
现有规则处理。

## 设计 HTML 的最小要求

### 1. 固定终端画布

每个场景必须标明终端列数和行数。默认使用 `120x34`。

HTML 中使用等宽字体，并保证设计区域具有固定行列。可以使用 `ch` 和固定行高模拟
字符单元，但设计标注必须写成“列”和“行”，不能只写像素。

### 2. 至少提供宽窄两个状态

普通界面至少展示：

- `80x20`：窄窗口。
- `120x34`：标准窗口。

涉及侧栏时，额外展示：

- `109` 列：侧栏隐藏。
- `110` 列：侧栏显示。

涉及较高表单或弹出卡片时，额外展示 `80x14` 的高度不足状态。

### 3. 明确内容溢出结果

不要只使用刚好放得下的示例文本。至少展示一条长文本，并直接画出期望结果：

- 换行；
- 截断；
- 省略；或者
- 滚动后显示的内容。

### 4. 明确交互状态

存在交互时，至少展示默认状态和焦点状态，并在 HTML 注释中写明：

```html
<!--
Terminal: 120x34
Keys: Up/Down changes focus; Enter confirms; Esc cancels
Focus order: approve -> deny
Overflow: description wraps; action row remains visible
Narrow layout: hide secondary description
-->
```

不需要为每个状态建立独立数据文件；在同一个 HTML 中提供状态切换或并排展示即可。

## 颜色和字符规则

### 颜色

使用项目已有的语义颜色，而不是为每个组件任意增加颜色。默认主题 `monokai-pro`
是固定深色调色板（Monokai Pro，https://monokai.pro ），HTML 设计稿可以直接使用
下列十六进制值：

| 语义角色 | 十六进制 | 用途 |
| --- | --- | --- |
| 背景 | `#2d2a2e` | 终端底色参考、反白光标的前景 |
| 面板 | `#221f22` | 内嵌面板底色 |
| 主文本 | `#fcfcfa` | 正文和用户输入 |
| 次要文本 | `#c1c0c0` | 助手正文、输入框 |
| 弱化文本 | `#939293` | 工具标签、页脚、提示 |
| 更弱文本 | `#727072` | 时间戳、占位符 |
| 分隔线 | `#5b595c` | 边框、分隔线 |
| 进度空槽 | `#403e41` | 进度条未填充部分 |
| 强调色 | `#78dce8` | 标题、命令标签、用户竖条 |
| 高亮强调色 | `#ab9df2` | 光标、模型名、焦点强调 |
| 警告色 | `#ff6188` | 错误、Plan Mode、Git 分支 |
| 选中背景 / 选中文字 | `#78dce8` / `#2d2a2e` | 拖选高亮 |

代码块语法高亮使用 chroma 的 `monokai` 样式。

其余内置主题（`codex`、`amber`、`mono`、`light`）沿用同一组语义角色，其中 `codex`
会继承真实终端的前景色和背景色。HTML 是固定参考效果，真实终端只要求保持语义和对
比度，不保证像素颜色完全一致。

### 字符

优先使用：

- ASCII 字符
- 常见中文和英文字符
- 项目已经使用的边框字符
- 项目已经使用的 `⬢`、`▌`、`┊` 等符号

避免使用 Emoji、组合字符、Nerd Font 图标和私有区字符。确实需要新符号时，先确认
它在 Go 的 `lipgloss.Width` 或 `xansi.StringWidth` 中占用的列数。

## 当前 HTML 快照的注意事项

项目可以使用 `fox render` 将 Go TUI 导出为自包含 HTML，用于与设计稿对照：

```bash
fox render -scene transcript -width 120 -height 34 -out transcript.html
fox render -scene permission-form -width 80 -height 20 -out permission.html
```

当前导出器可靠映射前景色、背景色、粗体、弱化、下划线和反色。Lip Gloss 还支持
斜体、删除线和闪烁，但不同终端支持程度不同，当前 HTML 导出器也没有完整映射它们。
因此设计可以少量使用斜体和删除线，但不能依赖它们表达关键信息；不要使用闪烁。

## 给 HTML 设计 Agent 的直接指令

下面的内容可以直接提供给负责生成 HTML 设计稿的 Agent：

```text
你正在为一个使用 Go Bubble Tea 和 Lip Gloss 实现的终端界面制作 HTML 设计稿。

请严格遵守以下规则：

1. 把 HTML 当作终端字符界面的预览，不要把它设计成普通网页。
2. TUI 画布使用等宽字体和固定行列，默认尺寸为 120x34。
3. 所有尺寸、边距、间距和边框都必须能换算成整数个字符列或行。
4. 只使用纯色前景和背景、粗体、弱化、下划线、反色、字符边框和文本布局。
5. 可以设计标题栏、状态栏、对话、输入框、菜单、列表、表单、侧栏、字符卡片、
   选择器、滚动区、进度条和离散帧加载动画。
6. 禁止使用不同字号、自定义字体、像素定位、圆角半径、阴影、渐变、透明度、
   毛玻璃、图片、SVG、Canvas、z-index、transform、CSS transition 和平滑动画。
7. 不要依赖浏览器自动换行。直接展示长文本的换行、截断、省略或滚动结果。
8. 不要使用未验证的 Emoji、Nerd Font 图标、私有区字符或复杂组合字符。
9. 交互不能只依赖 hover。必须展示键盘焦点和选中状态。
10. 普通界面提供 80x20 和 120x34 两种效果；涉及侧栏时再提供 109 和 110 列；
    涉及高表单时再提供 80x14。
11. 在 HTML 注释中写明终端尺寸、按键、焦点顺序、内容溢出方式和窄窗口降级方式。
12. 场景切换控件可以放在终端画布外，但画布外的网页 UI 不属于需要实现的 TUI。

如果某个视觉效果不符合这些规则，请主动改成最接近的字符界面效果，不要保留一个
无法使用 Bubble Tea 和 Lip Gloss 可靠实现的网页效果。
```

## 最简协作流程

1. 设计 Agent 按上述规则生成一个 HTML 文件。
2. 实现前先检查是否存在终端无法表达的效果。
3. 确认宽窄布局、焦点和长内容结果。
4. 使用 Bubble Tea 和 Lip Gloss 实现。
5. 使用相同终端尺寸运行 `fox render`，对照 HTML 设计稿。

这五步足以作为当前阶段的协作方式。只有在实际使用中反复出现设计和实现偏差时，
再增加自动检查或额外交付物。
